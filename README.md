# Needle Works: Haystack Industries

A browser-based 2D factory automation game about finding needles in haystacks — inspired by *Needle In A Haystack*, with entirely original code, art and UI.

Buy hay, tear bales apart, scan every portion for hidden needles, process the leftover hay into premium bales, polish needles into luxury goods, sell everything, research a 66-node technology tree, upgrade individual machines, power your factory, buy land and eventually franchise for permanent bonuses.

- **No build step, no backend.** Plain ES modules + Canvas 2D. Deploys to GitHub Pages as-is.
- **Offline-capable** (service worker) and **installable** (web manifest, "Add to Home Screen" on iPad).
- **Touch-first**: tap, drag-to-place, one-finger conveyor drawing, two-finger pan, pinch zoom, Apple Pencil hover previews. Full mouse & keyboard support too.
- **Autosaves** to `localStorage` every 30 s and when the tab is hidden; manual save, export and import of JSON save files.

## Run locally

```bash
npm start              # serves on http://localhost:8080 (uses npx http-server)
# or, with no Node at all:
python3 -m http.server 8080
```

Open `http://localhost:8080`. (Opening `index.html` directly from the file system will not work — browsers block ES modules on `file://`.)

## Deploy to GitHub Pages

1. Create a repository and push this folder to the `main` branch.
2. In **Settings → Pages**, set **Source** to **GitHub Actions**.
3. The included workflow (`.github/workflows/pages.yml`) runs the simulation tests, regenerates the offline cache list and publishes the site. Your game will be at `https://<user>.github.io/<repo>/`.

All asset paths are relative, so it works from a repository sub-path. Alternatively, set Pages to "Deploy from a branch → main / root" — no build is required.

After editing files, run `npm run build` to refresh `sw.js` (the offline cache list and version); the workflow does this automatically.

## Tests

```bash
npm run test:sim       # headless simulation scenarios (Node only)
npm install && npm run test:e2e   # browser tests driving the real UI (needs Google Chrome; set CHROME_PATH to override)
```

| Scenario | Covered by |
|---|---|
| A — Basic production (buy → break → transport → inspect → recover → store → sell) | `sim.test.mjs`, `e2e.test.mjs` (built with real mouse clicks) |
| B — Premium hay (dust → wash → dry → grade → compress → press → package → sell) | `sim.test.mjs` |
| C — Multi-line factory with splitters, mergers, storage; **item conservation** checks (no loss/duplication) | `sim.test.mjs` |
| D — Earn RP → research → unlock → buy → upgrade → faster production | both |
| E — Save → reload → identical factory, rotations, upgrades, research | both (real page reload) |
| F — iPad portrait & landscape: touch placement, rotation, conveyor drawing, pinch, pan, tech-tree touch scrolling, panel layout | `e2e.test.mjs` (CDP multi-touch) |

## Project structure

```
index.html                 entry page (viewport-fit=cover, safe areas)
manifest.webmanifest, sw.js offline / install support (sw.js generated by tools/build.mjs)
styles/main.css            UI, responsive & touch layout
assets/                    original logo/icons
src/
  main.js                  boot, main loop, debug API (window.game)
  core/   game.js (state, modifiers), util.js
  data/   resources.js, machines.js (55 machines), technologies.js (66 nodes), layouts.js
  sim/    world.js (grid, rotation, ports, connection validation), kinds.js (machine behaviours,
          transactional item transfer), power.js (networks & priority allocation), simulation.js (fixed 20 Hz step)
  systems/ economy.js (market, selling, orders, auto-sell), research.js, actions.js (build/upgrade/expand/prestige),
          milestones.js (milestones & guided goals), save.js, audio.js (synthesised SFX & ambience)
  render/ renderer.js, sprites.js (procedural machine art + animations), icons.js
  input/  input.js (pointer/touch/pencil/keyboard)
  ui/     hud.js, panel.js, screens.js (tech tree, market, stats, machines, storage, expansion, encyclopedia, settings, game), dom.js
tests/  sim.test.mjs, e2e.test.mjs, harness.mjs
tools/  build.mjs
```

The spec suggested Phaser 3; this uses a small custom Canvas engine instead so there is no dependency to download, the game works offline from the first load, and nothing needs bundling. Game data is data-driven JS modules rather than `.json` files so it loads synchronously and offline without `fetch`.

## Known limitations

- No offline progress: the factory only runs while the tab is open (it resumes exactly where it stopped).
- The power network is radius-based (no explicit wire placement); poles auto-link within range.
- Vertical Lifts jump a fixed 2 tiles rather than pairing with a chosen exit.
- Audio is synthesised; there is no music track.
- Very large factories (several thousand belt tiles) may lower frame rates on older iPads; "Reduce animations" in Settings helps.
- Balance has been checked for the early and mid game; late-game prices and research costs may want tuning after real play.
